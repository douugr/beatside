# BeatSide: agent guide

BeatSide is a retro wheel music player with two native apps: Android (Kotlin + Jetpack Compose)
and iOS (Swift + SwiftUI). Read `.specify/memory/constitution.md` before any work; it overrides
everything else, this file included.

## How work happens here

This project uses Spec-Driven Development with GitHub Spec Kit. The skills are in
`.claude/skills/`:

1. `/speckit-specify <feature description>` creates `specs/NNN-name/spec.md` and the branch.
2. `/speckit-clarify` (optional) resolves open questions in the spec.
3. `/speckit-plan` writes the technical plan for **both** platforms.
4. `/speckit-tasks` breaks the plan into tasks.
5. `/speckit-analyze` (optional) checks the artifacts against each other.
6. `/speckit-implement` executes the tasks.

Do not write app code without an accepted spec, plan and task list.

## Layout

```
android/    Android app (created by the first feature)
ios/        iOS app (created by the first feature; project generated by XcodeGen)
specs/      One directory per feature
.specify/   Spec Kit templates, scripts and the constitution
```

## Reference material

The branch `prototype/wheel-and-menus` has an early, never-compiled prototype (wheel tracker,
menu engine, LCD screen) and draft docs (`docs/WHEEL.md`, `docs/ARCHITECTURE.md`,
`docs/ROADMAP.md`). Use them as input for specs. Copy code from there only when it satisfies an
accepted spec and passes its tests.

## Commands

- Android unit tests: `cd android && ./gradlew :app:testDebugUnitTest`
- iOS: `cd ios && xcodegen generate`, then run tests from Xcode or with `xcodebuild test`.

## Conventions

- Conventional Commits.
- GitHub work goes through the `gh` CLI.
